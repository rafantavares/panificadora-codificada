Especificação · Panificadora Codificada

Documento oficial da Parte A (docs/especificacao.md) atendendo às 7 perguntas da disciplina de LFC.

1. Para que serve

A linguagem descreve receitas culinárias de forma estruturada: ingredientes com quantidade e unidade, e uma sequência de passos numerados. O objetivo é permitir que um programa leia a receita, separe os passos e valide medidas, tempos e temperaturas.

2. Programa de exemplo completo

# Receita minima                              (1) comentário, descartado
receita "Pao simples";                        (2) nome da receita
porcoes 4;                                    (3) rendimento

ingrediente farinha 500 g;                    (4) nome, quantidade, unidade
ingrediente agua 300 ml;                      (5) idem

passo 1:                                      (6) abre o passo 1 (vale até o próximo "passo N")
  misture farinha, agua;                      (7) ação sobre ingredientes separados por vírgula
passo 2:                                      (8) fecha o passo 1 e abre o passo 2
  asse por 40 min a 180 graus;                (9) ação + tempo + temperatura

3. Tipos de dado

TipoExemplosToken(s)
Número (inteiro ou real)500, 2.5NUMERO
Texto"Pao simples"TEXTO
Nome (ingrediente/variável)farinha, agua_mornaIDENT
Quantidade500 g, 1 colherNUMERO UNIDADE
Tempo40 min, 1 hNUMERO TEMPO
Temperatura180 grausNUMERO TEMPERATURA

Unidades: g, kg, ml, l, xicara, colher, pitada, un. Tempos: seg, min, h.

4. Comandos

  • receita "nome"; — nomeia a receita.
  • porcoes N; — rendimento.
  • ingrediente NOME QTD UNIDADE; — declara um ingrediente.
  • passo N: — inicia o passo N. Tudo até o próximo passo M pertence a ele.
  • Ações dentro de um passo: misture, adicione, bata, amasse, descanse, asse, cozinhe, unte, modele, sirva. Podem levar ingredientes separados por vírgula, textos e preposições (em por a ate com) seguidas de tempo/temperatura.
  • NOME = expressão; — atribuição de valor numérico (ex.: total = 1000 + 600 * 2;).

5. Operadores e Precedência

Do maior para o menor (ordem de precedência no compilador):

  1. ( ) — agrupamento
  2. *, / — multiplicação e divisão (esquerda para a direita)
  3. +, - — soma e subtração (esquerda para a direita)
  4. = — atribuição

6. Comentários

Começam com # e vão até o fim da linha. São descartados (-> skip) pelo analisador. (O padrão // foi deliberadamente descartado porque a barra / já é usada para divisão em frações como 1/2 xicara).

7. Três coisas que a linguagem deliberadamente não faz

  1. Não tem laços nem condicionais: Uma receita culinária é uma sequência linear e determinística; expressões humanas como "repita até dourar" são descritivas, não lógica executável.
  2. Não converte unidades automaticamente: A conversão de g para xicara depende da densidade de cada ingrediente (200g de farinha é diferente de 200g de manteiga).
  3. Não tem tipos definidos pelo usuário nem funções: Apenas os tipos da seção 3 existem; receitas não chamam outras receitas como sub-rotinas.

Gramáticas ANTLR 4 (.g4)

Comparativo entre a gramática da E2 (apenas léxico) e da E3 (sintático completo com regras livres de contexto).

🌳 E3: sintatica/gramatica/Receita.g4
Parser + Lexer 
grammar Receita;

// ==========================================
// PARSER (E3): REGRAS EM MINÚSCULAS
// ==========================================
programa
    : declaracao_receita? declaracao_porcoes? declaracao_global* bloco_passo* EOF
    ;

declaracao_receita
    : RECEITA TEXTO PONTOVIRG
    ;

declaracao_porcoes
    : PORCOES NUMERO PONTOVIRG
    ;

declaracao_global
    : declaracao_ingrediente
    | atribuicao
    ;

declaracao_ingrediente
    : INGREDIENTE IDENT expr UNIDADE PONTOVIRG
    ;

atribuicao
    : IDENT IGUAL expr PONTOVIRG
    ;

bloco_passo
    : PASSO DOISPONTOS comando_passo*
    ;

comando_passo
    : comando_acao
    | atribuicao
    ;

comando_acao
    : ACAO lista_argumentos? modificador* PONTOVIRG
    ;

lista_argumentos
    : argumento (VIRGULA argumento)*
    ;

argumento
    : IDENT | TEXTO
    ;

modificador
    : PREPOSICAO complemento
    ;

complemento
    : expr (TEMPO | TEMPERATURA)?
    | IDENT | TEXTO
    ;

// Precedência de operadores no ANTLR:
expr
    : ABREPAR expr FECHAPAR
    | expr (VEZES | DIV) expr
    | expr (MAIS | MENOS) expr
    | NUMERO
    | IDENT
    ;

// ==========================================
// LEXER (E2): REGRAS EM MAIÚSCULAS
// ==========================================

programa : .*? EOF ;

Diário de Bordo & Decisões Arquiteturais

23/09 — Concepção do Domínio e Ambiguidade Léxica

Definimos o domínio (leitor de receitas) e a ideia central: passo N abre um bloco. No léxico, transformamos PASSO em um token único ('passo' [ \t]* [0-9]+), permitindo que tanto passo 1 quanto passo1 funcionem sem ambiguidade.

23/09 — Decisão de Comentários (# vs //)

Escolhemos # para comentários porque a barra / já é usada como divisão em frações numéricas (ex: 1/2 xicara). Usar // traria conflitos léxicos desnecessários com operadores aritméticos.

23/09 — Gramática Combinada para antlr4-parse

Ao rodar antlr4-parse, o ANTLR exigiu uma regra de parser. Trocamos para grammar Receita; com o stub programa : .*? EOF ;. Isso permitiu testes imediatos sem compilar código e preparou o terreno perfeito para a E3.

14/10 — Implementação da Etapa E3 (Parser & Árvore Sintática)

Substituímos o stub provisório pela gramática sintática completa em sintatica/, com precedência de operadores e geração automatizada da Árvore Sintática (CST/AST) para todas as receitas.
